# Guide for reviewers

This guide is for a reader who has the thesis chapter *A Task-Aware Validation Protocol for Generative
Models of Financial Time Series* and wants to check that its results follow from the code and the data.
It gives a reading path from the chapter to the repository and three levels of verification.

## 1. Where to find what

| In the chapter | In the repository |
|---|---|
| Section 3, the induced-law framework | `docs/PROTOCOL.md`; `src/tavp/tasks/` (rules, backtest, functionals, equivalence tests) |
| Section 4, the protocol and its levels | `docs/PROTOCOL.md`; `src/tavp/protocol/` (`l1.py`, `task_levels.py` for L2-L3, `l4.py`, `card.py`) |
| Section 4.4, pre-registration and registry of the experiments | `configs/preregistration.yaml` (tag `prereg`); `docs/DEVIATIONS.md`; `docs/ADDENDUM_QGAN.md` (tag `prereg-qgan`); `docs/EXPERIMENTS.md` |
| Section 5, known-answer tests | `src/tavp/dgp/` (processes), `src/tavp/perturb/` (planted defects), experiments E1, E2, E6, E12 |
| Section 6.1, the TC-VAE (pre-registered) | `third_party/tcvae/` (authors' code), `src/tavp/generators/tcvae.py`, experiments E4-E6 |
| Section 6.2, the Quant GAN (addendum) | `src/tavp/generators/qgan.py`, experiments Q0, Q0b, E13 |
| Section 6.3, analyses added after the results | experiments E8-E11, `src/tavp/report/tolcrit.py`; `docs/DATA.md` for the market data |
| Every number, table and figure | `thesis_assets/` (generated by `make thesis`); each number is a macro `\tavp{key}` defined in `thesis_assets/numbers.tex` and computed in `src/tavp/report/` |
| Appendix, settings and deviations | `configs/full.yaml`, `configs/real.yaml`, `docs/DEVIATIONS.md` |

`docs/EXPERIMENTS.md` maps each experiment to its command, its outputs and the section that reports it.

## 2. Three levels of verification

All commands run from the root of the repository, after `uv sync` (Python 3.12 and
[uv](https://docs.astral.sh/uv/); about two minutes).

### Level 1: the numbers of the chapter (about five minutes)

```sh
make test            # unit tests of processes, defects, functionals, levels and generators
make verify-frozen   # expected last line: VERIFIED
```

`results/frozen/` is the snapshot of the results used in the chapter (a few hundred tables, with a
manifest of SHA-256 hashes). `make verify-frozen` checks the manifest, rebuilds every table, figure
and number of the chapter from the snapshot with the code of the repository, and compares the numbers
with those in `thesis_assets/numbers.tex`; it reports the files altered and the numbers that differ,
are missing or are new. No data download and no training is needed.

### Level 2: the pipeline runs end to end (15-30 minutes)

```sh
make quick J=4       # the simulated studies with small sizes, written to results/quick/
```

The smoke run covers training, the known-answer tests (E1, E2, E6, E12), the pre-registered case study
(E4-E7) and the analyses E8 and E9, with small sizes; it leaves out the market data, which need a
download, and the Quant GAN, which needs hours of training or a GPU. Its numbers are not those of the
chapter; the point is that every step, from training to the tables, runs from a clean copy. On the thesis machine a fresh clone in a new
environment reproduced the trained generators bit for bit and all the numbers of the smoke run.

### Level 3: the full study (about 25 hours on a 12-core laptop)

```sh
make all             # training, known-answer tests, case study, robustness, market data, Quant GAN
make verify          # compare the regenerated numbers with the frozen ones
```

Steps can be run separately (see `REPRODUCE.md`); experiments that run many tasks cache each task
under `results/<experiment>/tasks/`, so an interrupted run resumes where it stopped. A single
experiment can be checked on its own, for example the negative control (`make` target `meta`, first
command) or one figure (`make thesis` after any experiment).

## 3. Checking the pre-registration

```sh
git tag -n1                                          # prereg, prereg-qgan, thesis-v1
git show prereg:configs/preregistration.yaml         # settings and hypotheses before any experiment
git diff prereg -- configs/preregistration.yaml      # empty: the file was never changed
git log --oneline prereg..HEAD                       # what happened afterwards, in order
```

Every later change of a setting and every analysis added after the results is in
`docs/DEVIATIONS.md` (D1-D10), with its date and reason; results under the pre-registered settings are
kept alongside (for example the columns `p_prereg` of level L1). The second deep generator was
pre-registered by `docs/ADDENDUM_QGAN.md` under the tag `prereg-qgan`; the single tuning round of its
fidelity check was committed before it was run (commit `7dd24de`).

## 4. Determinism and hardware

All random numbers derive from one master seed through named streams (`tavp.utils.rng`). On the same
platform and library versions every result is reproduced exactly. Neural training and floating-point
reductions can differ in the last digits across platforms; such differences propagate to the trained
generators and may change some numbers of the case study slightly, while the known-answer tests, which
use only the oracles, are unaffected. The Quant GAN trains and samples on the Apple GPU (MPS) when
available, deterministically on the same machine; on other machines it runs on the CPU, much more
slowly, and its outputs differ from those on the GPU by floating-point rounding.

## 5. What is not included

- The market data, which are copyrighted: `python scripts/get_french.py` downloads them (`docs/DATA.md`).
  Level 1 does not need them.
- The trained generators (about 150 MB): they are regenerated by the training steps of `make all`.
- Tail-GAN, which is GPL-3.0 and is only discussed in the chapter: `python scripts/get_tailgan.py`.
